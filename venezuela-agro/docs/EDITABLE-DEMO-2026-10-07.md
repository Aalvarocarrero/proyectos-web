# Editable demonstration workspace

`/finca-demo` is an identity-free, local practice workspace. A separate IndexedDB database holds one initialized snapshot with revision and reset generation. There is no outbox or account import. It starts with 1 fictional farm, 56 records across the eight implemented record types, and 2 nonpublishable draft examples. Eight inventory categories have licensed illustrative photos with source/author/license/change credits.

The demonstration is shared within the browser and is explicitly labelled unsuitable for real/personal data. Existing account/device farm stores are untouched. The root layout does not mount real synchronization, offline account choice or feedback services on this route. Exiting uses a normal document link. The service worker prepares this shell explicitly for offline reopening.

Users can create, edit and delete demo records and listing drafts; adjust the sketch, move/reshape/split supported areas; edit or delete the entire fictional farm; and explicitly reset the original examples. Deleting an animal removes its demo weights atomically. A deleted collection never re-seeds itself. A stale form or tab cannot overwrite a newer revision/reset. Local quota/transaction failures preserve the previous snapshot. Plan totals are recalculated; latest animal weights are derived from remaining dated records.

A separate demo-backup format prevents confusing exported practice data with an importable real-farm backup. There is no automatic promotion to real records. First-start invitation appears only after normal workspace loading completes and confirms there is no farm. Choosing an empty real farm only dismisses the invitation, never clears storage. Existing farms retain an optional demo link.

This is practice coverage of existing sections, not a new set of real business functions. Public registration examples, where shown, remain previews. Satellite coverage is still the explicitly labelled fixed public sample from the previous release; the demonstration has no invented geographic coordinates or satellite download.

Verification uses synthetic IndexedDB stores and source/component tests. No real account data was edited. Physical iOS/Android keyboard, installed-app lifecycle and touch performance remain device checks.

## Public registration examples

The Fincas directory also offers six selectable, read-only example cards matching all current farm-type choices: Productora, Turística, Mixta, Cultivos y cosechas, Transformación de alimentos and Propiedad en venta. Each dialog exposes the full registration structure and explicit fictional-data notice. Phone fields deliberately contain no number; social links are empty. Selecting an example never fills or submits the real form, creates a queue entry or counts it as an active public farm. Users must separately supply their own registration data, contact and authorization. These six previews are distinct from the editable private-management demonstration.

## Animal-history revision (fixture version 2)

The original fixture had four unique animals and twelve separate weight cards; the repeated headings made each measurement look like a duplicated animal. Both animal and weight views now group dated readings under one animal card. Reading order is chronological, with each distinct measurement editable/deletable.

New/reset demonstrations contain one bovine, one pig and one hen, with ten dated weight readings and 56 management records overall. The pig example uses 60, 70, 80 and 120 kg on distinct fictional dates. This is an illustrative fattening scenario, not a biological limit or weighing schedule. Existing practice records, including user edits and older sample animals, remain untouched until an explicit confirmed reset. A fixture-version notice explains this choice.

Management categories now use consistent semantic SVG icons, including a fence for pasture/corrals, a pig for porcines and a chicken for poultry. Existing farm data and category strings are unchanged. Tests assert unique animal cards, unique chronological measurement entries, typed relationships, preserved old demo edits and no 120 kg validation cap.
